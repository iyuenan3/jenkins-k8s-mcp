# 项目身份

名称：Jenkins K8s MCP。slug：jenkins-k8s-mcp。

使命：让个人及其他独立使用者通过统一 MCP 接口管理自己的 Jenkins 与 Kubernetes，跨项目使用时只需配置连接。

生命周期：active。当前为立项后的 pre-code 阶段，能力尚未实现。

## 产品边界

产品以平台原生对象为管理单位。Jenkins 和 K8s 模块可独立启用，复用统一的连接、操作和结果机制。

具体能力范围及验收归 PRD；对外协议、授权和错误语义归 SPEC；结构归 ARCHITECTURE。

## Non-Goals

- Apollo、数据库管理和具体公司的发布目录不属于本产品范围。
- Git 中的 Jenkinsfile、Helm 或 GitOps 源文件修改属于另行扩展的源码管理能力；本范围管理 Jenkins 与 K8s API 对象。
- 当前以每个使用者独立部署为基础，不建设组织级多租户控制平台。
- 本轮立项不包含服务实现、安装到真实环境或业务资源变更。

## 绝不

- 不把组织、服务、环境、Job 命名、namespace、分支或私网地址硬编码为产品规则。
- 不把私钥、token、kubeconfig、Secret 原值或真实私有环境配置写进仓库、日志和长期审计。
- 不把模型回填的确认文字或 actor_id 当成可信的人类身份凭证。
- 不因 MCP 接入而隐式修改平台账号权限、Jenkins Job 或业务资源。
- 不把 API 接受请求、构建成功、资源就绪和业务验收合并成一个成功结论。
- 不用最新构建或其他操作者的更新替代本次操作的结果。
- 不在结果未知时自动重试可能重复触发的写操作。
- 不在运行中修改全局 kubeconfig current-context 来切换目标。
- 不把已确认的 Secret、通用资源修改、Job 删除或 exec 范围静默缩减为只读工具。
- 不自动丢弃本工具的操作记录或可恢复历史。业务资源删除作为显式管理能力独立处理。
