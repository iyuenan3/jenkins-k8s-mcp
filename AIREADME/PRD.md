# 产品需求

2026-10-19 立项。本文记录用户已确认的范围。以下能力均为需求，当前没有实现或真实系统验收。

## 用户与问题

首要使用者为需要跨项目管理多套 Jenkins 和 K8s 的个人。其他使用者也应能安装同一个产品，配置自己的连接后开始使用。

当前问题是操作分散、目标容易混淆、日志和状态难以连续跟踪，专用工具又容易绑定一家公司或固定环境。产品需要让 AI 获取明确对象和可靠证据，并完成管理操作。

## 目标与成功标准

- 接入新的 Jenkins 或 K8s 时，只改使用者配置，不改产品源码。
- Jenkins 和 K8s 可分别工作，也可按用户提供的关联一起使用。
- 管理操作广覆盖，能力目录逐项标明依赖、实现和验证状态。
- 查询、变更、长操作跟踪和结果核验有一致的目标和状态表达。
- 本地与远程两种入口复用同一执行逻辑，配置体验和结果语义一致。

## 交互原则

目标可发现、可核对。同名对象存在歧义时返回候选；写操作执行前固定完整目标和实际参数。

查询直接返回有界结果。明确的写入请求默认沿用客户端审批，不强制额外复制确认口令；可按连接启用预览后的额外确认，精确契约见 SPEC。

MCP 汇集证据并执行操作，客户端中的 AI 负责解释、推理和组织工作流。诊断工具不因发现异常自动进行修复。

## 验收要求

| 场景 | 必须取得的证据 |
| --- | --- |
| 跨项目接入 | 不同连接、Job 类型与集群配置可仅通过配置切换，同名对象不会串目标 |
| Job 管理 | 配置写入后回读；未知插件字段保留；创建、复制、修改、启停和删除逐项验证 |
| 构建 | 原生 Queue 与 Build 可归属本次操作；日志游标可续读；并发他人构建不影响归属 |
| 重启与扩缩容 | 观察本次更新与目标数量、就绪情况、失败原因，区分请求接受和实际收敛 |
| 配置 | 变更差异及原始版本可核对；分别说明写入、传播或重启需求，以及实际生效证据 |
| Secret | 显式查询和修改可用；默认诊断摘要、运行日志和持久审计不复制敏感原值 |
| exec | 目标容器与 argv 准确；输出、退出状态和超时可区分；超时不冒称远端进程已终止 |
| 异常与恢复 | 权限拒绝、并发冲突、断线、结果未知、部分成功和重连均有可回查状态 |
| 交付 | 干净环境可安装；stdio 与 HTTP 行为一致；真实配置和历史数据不进入分发包 |

假 IO 测试用于回归与失败路径；真实平台读写验收是独立证据，使用用户明确指定并授权的对象。单项通过不外推整个平台或所有版本兼容。

## 关键假设与待验证风险

- Jenkins 插件和 Job 类型有差异，参数与配置能力需实查，不能从一个样本推断通用支持。
- K8s 配置写入与应用生效存在不同路径，自动控制器也可能继续调整资源。
- 客户端审批、MCP 访问认证和平台权限是不同层次，需要在真实客户端验证边界。
- exec 和日志可能持续输出，必须验证限时、截断、断线和远端执行结果未知的表达。
- 广覆盖会增加工具数量，需要通过明确参数、能力发现和有界结果验证实际可用性。
