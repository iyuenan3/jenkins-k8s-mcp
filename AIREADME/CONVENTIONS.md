# 工程约定

## 身份与命名

项目 slug 固定为 jenkins-k8s-mcp。代码、工具和模块命名围绕平台对象与动作，避免组织名、项目名和环境缩写。

工具 schema 与配置先建立单一来源，生成文档和运行清单均从实际注册能力取得。

## 实现默认值

Python 执行核心与 MCP 入口分离，两个平台适配器独立测试。具体依赖、最低版本和发布方式在首次编码时根据实际支持核验。

连接实例和请求目标不可变地绑定；异步请求不共享可被其他请求切换的全局目标。

查询采用有界输出，原生日志保留游标与截断状态。协议输出与进程日志分离，stdio 入口不能把调试日志写入协议输出流。

写入在统一执行路径中处理；插件、类型和原生权限差异如实返回，不伪装为通用成功。

## 验证

单元与契约测试使用假的平台 IO，覆盖真实执行核心、参数、目标、状态和敏感数据路径。真实平台验收与这些测试独立记录。

首轮代码建立后补入可运行的测试、构建、安装和兼容性验证命令。当前不存在这些命令，不把文档检查称作应用测试。

文档校验命令：在项目根运行 `bash ~/.agents/skills/aireadme/scripts/check.sh`。漂移检查追加 `--drift`。

## 文档与历史

中文使用中文标点，不使用破折号；日期使用 Asia/Shanghai。

产品目标、接口、结构、部署事实和决策各按 INDEX 指向的职责维护。DECISIONS、MEMORY、CHANGELOG 追加新记录，不覆盖历史结论。

用户授权提交后精确暂存文件。内容提交和后续 AIREADME 锚点提交分开，保留其他未提交改动。推送和发布需要各自的明确授权。
